# 文件引用与关系图

Loom 从 Markdown 和画板文件里提取内部引用，并在关系图中显示「哪个文件引用了哪个文件」。原文件是引用的事实来源。关系图和素材详情读取同一份引用结果，详情可以从被引用文件查看反向链接。

## Obsidian 的行为

| 来源 | 图谱中的表现 |
| --- | --- |
| 正文内链 | `[[产品说明]]` 和 `[产品说明](产品说明.md)` 都建立文件间的连边。显示名称、`#标题` 和 `#^块标识` 用于显示或定位，关系指向目标文件。[内部链接](https://obsidian.md/help/links) |
| 正文嵌入 | `![[架构图.png]]` 是内部引用，开启「附件」后可在图谱中显示附件节点。[嵌入文件](https://obsidian.md/help/embeds) · [图谱筛选](https://obsidian.md/help/plugins/graph) |
| YAML 属性 | 文本或列表属性里的内链也被索引，例如 `项目: "[[产品说明]]"`。[属性](https://obsidian.md/help/properties) · [内部链接索引](https://obsidian.md/help/bases/syntax) |
| 画板文件卡片 | 从 Obsidian 1.12 起，画板里的文件引用计入反向链接和图谱。[1.12 更新记录](https://obsidian.md/changelog/2026-02-27-desktop-v1.12.4/) |

反向链接是从目标文件查看已有的引用。未链接提及可以在反向链接面板中查找。Mermaid 的可点击内链只在图表中使用。把画板上两张文件卡片之间的箭头投射为全库连边，是 Advanced Canvas 插件的可选功能。[反向链接](https://obsidian.md/help/plugins/backlinks) · [Mermaid 内链](https://obsidian.md/help/advanced-syntax) · [Advanced Canvas 发布说明](https://forum.obsidian.md/t/canvas-links-in-cards-and-outgoing-arrows-in-graph-view/49697/103)

## Loom 第一版

| 文件内容 | 自动关系 |
| --- | --- |
| `脚本.md` 写了 `[[产品说明]]` 或普通 Markdown 内链 | `脚本.md` → `产品说明.md` |
| `脚本.md` 写了 `![[架构图.png]]` 或普通 Markdown 内部图片链接 | `脚本.md` → `架构图.png` |
| `分镜.canvas` 有一张引用 `演示.mp4` 的素材卡片 | `分镜.canvas` → `演示.mp4` |

- **解析 Markdown。** 正文支持 Wiki 链接、嵌入和普通 Markdown 内链，第一版不解析 YAML。使用 Markdown 解析器识别正文语法，代码和示例中的链接样式按原文显示。预览和索引共用同一套路径解析。
- **定位目标。** Wiki 链接里的目录从库根目录开始，普通 Markdown 相对链接从源文件所在目录解析。省略扩展名时按 Markdown 文件查找。只认完整路径，不按文件名在整个库里搜索：`[[说明]]` 只匹配库根目录下的 `说明.md`，其他目录的文件要写 `[[产品/说明]]`，因此不存在重名歧义。预览点击链接可打开对应素材，标题锚点用于文件内跳转。
- **解析画板。** 按 [画板的素材引用规则](./CANVAS.zh-CN.md#素材引用) 读取文件卡片，优先使用 `loom.assetId`，标准画板按 `file` 路径解析。两张卡片之间的箭头表达画板内的关系。
- **显示与去重。** Graph 标出关系来自 Markdown、画板或手动创建。一个文件多次引用同一素材时合并显示。同一对文件既有自动引用又有手工关系时，分别显示两条。去掉最后一处引用后自动移除对应的边。无法解析的引用在源文件预览中标红，表示引用错误，不在 Graph 中生成节点或边，等目标出现后重新解析。

Loom 不做标签节点：关系图只表达文件之间的引用，标签不是文件。

Loom 不做待创建节点：引用的文件不存在属于引用错误，按上文标红提示。

Markdown 链接改名回写，以及将画板箭头加入全库关系图，可作为后续独立功能评估。

## 索引与更新

1. **打开库时构建索引。** 扫描库里的 `.md` 和 `.canvas`，记录引用来源和解析后的目标素材 ID。同一文件的正文和重复卡片共享去重规则。
2. **复用文件变更监听。** 保存时只重读变更的源文件。素材新增、改名、移动或移除时，重新解析受影响的引用。画板编辑、Agent 写入、外部编辑和云端拉取通过同一套更新机制生效。[素材库监听](../packages/core/src/library/library.ts)
3. **自动引用单独成表，与手工关系同库。** 自动引用写入图数据库中独立的边表（暂名 `REFERENCE`），手工关系继续使用 `RELATED`，互不影响，已有库无需迁移。`REFERENCE` 边只记录起点、终点和来源（`markdown` 或 `canvas`），关系类型固定显示为 `reference`。更新时删除某个源文件的全部 `REFERENCE` 边再写入新结果。图存储读取时合并两张表，Graph、反向链接对外不区分来源；多跳查询同时遍历两张表。自动引用由原文件恢复，图数据库中的副本丢失时可重新扫描重建，只能通过修改源文件删除。[现有关系读取](../packages/core/src/local-core.ts)

## 验证

- 用同一篇 Markdown 覆盖正文内链、嵌入、中文路径、标题锚点、代码示例和不同目录下的同名文件，核对预览打开的文件与 Graph 指向一致。
- 在画板内重复加入同一个视频，确认 Graph 只有一条由画板指向视频的边。移除最后一张卡片后自动边消失，同一对文件的手工关系仍可查询。
- 验证通过外部编辑器或 Agent 修改文件，以及云端拉取后重新打开库时，Graph 和反向链接会更新。
