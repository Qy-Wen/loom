# 画板设计

画板是素材库里围绕一个项目或问题组织素材的工作区。文件夹管理素材的位置，画板记录素材在当前任务中的用途，关系图记录整个素材库共享的事实关系。画板上的连线属于当前文档。

## 使用场景

| 场景 | 画板产出 |
| --- | --- |
| 素材策展与创作构思 | 把参考图、视频片段、文案和配音排成「开场」「演示」「结尾」，在素材旁写拍摄或剪辑备注。 |
| 跨文件的知识关联 | 把技术文档、架构图、会议录音和代码放到同一张画板，用「参考」「演进」「依赖」标注它们在当前问题中的联系。 |
| Agent 辅助研究 | 用户可以让 Agent 补充相关素材、整理对比笔记或连接结论与来源，并在画板上继续编辑。 |

## 第一版

1. 在素材库内新建或打开 `.canvas` 文件。在工作区标签中编辑，复用素材库已有的重命名、移动和删除操作。
2. 从素材库拖入一个或多个文件，生成素材卡片。支持创建 Markdown 文本卡片、带标题的分组和带标签的连线。
3. 支持平移、缩放、移动、调整卡片大小、框选、批量移动和撤销重做。单击选中卡片，按住卡片即可拖动。删除卡片时一并移除连接到该卡片的线。
4. 素材卡片显示文件名和可用缩略图。`.md` 卡片在画板内显示可滚动的正文预览。双击卡片打开 Loom 现有的素材预览，视频和音频由预览按需加载。
5. 编辑自动保存。关闭画板后再次打开，卡片、分组、连线和布局都能恢复。

首个验收场景是做一期产品介绍视频。用户可以在一个项目目录里新建画板，放入参考图、演示视频和配音，按分镜排列，加上文案和顺序说明，然后从卡片打开对应素材。

## 文件格式

每张画板是素材库内一个普通的 UTF-8 JSON 文件，名称使用 `.canvas` 后缀，文件名作为画板标题。基础结构沿用 [JSON Canvas 1.0](https://jsoncanvas.org/spec/1.0/)。`nodes` 存储卡片与分组，数组顺序表示从底到顶的叠放顺序。连线以卡片 ID 指定两端，必须用 `fromSide` 和 `toSide` 记录端点所在的边，移动卡片时端点仍接在原来的边上。位置和尺寸记录为画板坐标系中的整数。

```json
{
  "nodes": [
    {
      "id": "opening-note",
      "type": "text",
      "x": 0,
      "y": 0,
      "width": 260,
      "height": 140,
      "text": "## 开场\n先展示用户遇到的问题。"
    },
    {
      "id": "opening-video",
      "type": "file",
      "x": 360,
      "y": 0,
      "width": 320,
      "height": 200,
      "file": "视频素材/产品演示.mp4",
      "loom": { "assetId": "f2d1fecd-1e44-48c9-aab0-1633c980c592" }
    }
  ],
  "edges": [
    {
      "id": "opening-cut",
      "fromNode": "opening-note",
      "fromSide": "right",
      "toNode": "opening-video",
      "toSide": "left",
      "label": "接演示片段"
    }
  ]
}
```

标准的 `group` 节点用位置、尺寸和 `label` 表示分组。视口位置、缩放和选中项属于本机界面状态。读取和保存时保留可解析的扩展字段。其他编辑器能否保留 `loom` 扩展取决于其实现，标准的 `file` 字段仍提供可移植的路径引用。

### 素材引用

- **卡片引用素材。** 拖入库内文件时，画板保存卡片布局、素材 ID 和相对路径。预览从原文件或现有缩略图读取。多张卡片或多个画板可以共用同一个素材，删除卡片只影响画板文档。
- **卡片 ID 与素材 ID 独立。** `id` 标识画板里的卡片，`loom.assetId` 标识素材库中的文件。同一素材放两次时，两张卡片有独立的 ID 和连线。
- **按素材 ID 优先解析。** 素材改名或移动后，能通过 `assetId` 解析的卡片继续显示素材，下次保存画板时更新 `file`。路径以素材库根目录为基准，统一用 `/`，所以画板在库内移动后仍能解析引用。
- **用路径读取标准画板。** 卡片只有 `file` 时，在当前素材库内按路径解析。带有 `assetId` 的卡片解析失败时，保留布局、连线和上一次记录的路径，标记为「素材缺失」。同路径文件可以作为重新关联的候选，由用户确认。

## 保存与云备份

- 文档模块校验节点、连线及路径。主进程负责读写当前素材库中的画板，读取失败时保留原文件并显示错误。编辑器负责交互、撤销及预览。
- 拖动结束后提交布局修改。自动保存合并短时间内的连续编辑，每张画板的写入串行执行，通过临时文件原子替换。切换素材库和发起备份或拉取前，先完成待保存的编辑。画板在磁盘上的内容发生外部变化时，提示用户处理冲突。
- `.canvas` 跟随普通文件进入现有[云备份及恢复流程](./CLOUD-BACKUP.zh-CN.md)。两台设备都改了同一画板时，沿用现有的文件级冲突选择。跨设备恢复引用时，以恢复后的素材库及其素材索引为准。

## Agent 的画板操作

Agent 可以新建和读取画板，也可以在已有画板上添加、编辑或移除素材卡片、文本卡片、分组和连线，并调整布局。添加素材时沿用画板的素材引用规则。

用户通过对话决定要操作哪张画板、完成什么任务。Agent 与手动编辑共用文档校验和保存逻辑，操作沿用现有的工具权限机制。

## 验证

- 在 macOS 和 Windows 上验证新建、重新打开、移动画板和预览同一素材，覆盖中文文件名及多层目录。
- 将同一视频放入两个画板，确认磁盘上只保留一份视频。移动或改名后仍可预览，删除原文件后卡片保留且显示缺失状态。
- 验证标准 JSON Canvas 的读写、保存失败时原文件完整、外部改动提示，以及备份恢复后画板和素材引用一致。
