# Markdown 编辑

在 Loom 里直接编辑素材库中的 `.md` 文件。文件始终是普通 Markdown 文本，Agent、外部编辑器、云备份和[文件引用](./GRAPH-LINKS.zh-CN.md)都直接读取它，编辑器不引入自己的存储格式。

## 参考

| 产品 | 做法 |
| --- | --- |
| Typora、Obsidian 实时预览 | 直接编辑 Markdown 原文，用装饰把标题、粗体、链接渲染成成品样子，光标所在行显示原始符号。文本是唯一数据，不存在往返改写。 |
| Notion | 文档是块树，Markdown 只用于导入导出。每次保存都由块树重新生成文本，会规范化原文格式，不适合文件本身就是数据的场景。 |
| VS Code | 默认手动保存，标签标记未保存；可选延迟自动保存或失焦保存。磁盘文件被外部修改时，无未保存内容就静默重载，有未保存内容则在保存时提示。 |

Loom 采用第一种：基于原文的实时预览。

## 第一版

1. **预览标签内直接编辑。** 现有"预览"和"源码"两个标签合并为一个编辑视图加"源码"兜底，不再要求先切换模式再编辑。
2. **实时渲染。** 标题、粗体、斜体、行内代码、链接、列表、引用、任务列表、分隔线在编辑中即时显示成品样式。光标进入某个元素时显示它的 Markdown 符号。
3. **沿用现有渲染。** Wiki 链接和 `![[嵌入]]` 的路径解析、红色错误标记、点击跳转和标题锚点，复用[文件引用](./GRAPH-LINKS.zh-CN.md)的同一套解析。公式、Mermaid、表格和图片以渲染结果显示，光标进入时展开为源码。
4. **自动保存。** 停止输入约一秒后保存，失焦和切换标签时立即保存。标签上显示未保存标记。
5. **不改动不写盘。** 只有内容真的变化才写文件。编辑器不重排用户没有改动的文本。
6. **斜杠命令。** 行首输入 `/` 唤起菜单，插入标题、列表、任务、代码块、表格、引用、分隔线、公式和 Mermaid，以及链接到其他素材。菜单只负责插入 Markdown 文本。
7. **撤销重做。** 保留编辑会话内的撤销栈，保存不清空它。

块拖拽、块工具栏和多列等 Notion 式的块交互需要块树数据模型，与"文件是唯一数据"冲突，第一版不做。

## 编辑器

使用 [CodeMirror 6](https://codemirror.net/)，它直接编辑文本，并提供装饰、折叠、输入法和撤销栈。Markdown 语法树来自 `@codemirror/lang-markdown`。实时渲染由语法树上的装饰实现，Wiki 链接作为扩展语法单独识别，规则与 `references.ts` 保持一致。

编辑器只放在渲染进程，不进入 `@loom/core`。保存在应用主进程的 `MarkdownStore` 里，与画板的 `CanvasStore` 同级，核心不参与。

### 与现有解析的分工

项目里会同时有两个 Markdown 解析器，各管各的，互不调用：

| 解析器 | 负责 |
| --- | --- |
| markdown-it（含 texmath、KaTeX、Mermaid） | 渲染 HTML：只读预览、聊天、画板卡片；以及 core 的引用提取。 |
| Lezer（`@codemirror/lang-markdown`） | 只在编辑视图里生成带源码偏移量的语法树，用于装饰。markdown-it 的行内 token 没有偏移量，做不了这件事。 |

不把两者统一：Lezer 不产出 HTML，统一就要自写一个渲染层，风险大于收益；只把引用提取换成 Lezer，反而让"预览打开的文件与关系图一致"失去保证。

同一个语法会被两处各认一遍，漂移的风险按下面的办法收口：

1. **Wiki 链接只有一份规则**：`references.ts` 的 `matchWikiLink` 和 `findWikiLinks`。预览的行内规则、引用提取和编辑器装饰都调用它，不各写正则。路径解析同样共用一份。
2. **公式和 Mermaid 不重新实现**：光标不在其中时，编辑器直接调用现有的 KaTeX 和 Mermaid 渲染；公式的 `$` 界定规则和 texmath 保持一致。
3. **普通语法以样例测试为准**：同一批 Markdown 片段，同时检查预览、引用提取和编辑器各自认出的链接是否一致，覆盖代码块、行内代码、转义和表格。
4. **懒加载**：编辑视图和 `MarkdownPreview` 一样按需加载，CodeMirror 不影响启动体积。

## 保存与冲突

沿用画板 `CanvasStore` 的做法，不另建机制：

1. 读取返回文本和 revision（内容哈希）。
2. 保存带上读取时的 revision。磁盘内容已变化则返回冲突，不写入。
3. 原子写入，提交前再检查文件身份和时间戳，防止读取与写入之间被外部改动。
4. 串行队列，同一个文件的保存按顺序执行。
5. 文件上限与预览一致（2 MiB），超过时只读并提示。

写入后素材库监听会触发[引用更新](./GRAPH-LINKS.zh-CN.md#引用提取与更新)，关系图随之变化，保存路径不需要额外处理。

编码与换行：按 UTF-8 读写，保留文件原有的换行风格和开头的 BOM，新建内容使用 `\n`。

## 外部修改

规则与 VS Code 一致：

| 编辑器状态 | 磁盘文件被改动时 |
| --- | --- |
| 没有未保存内容 | 静默重新载入，保留滚动位置。 |
| 有未保存内容 | 不打断输入。保存时发现冲突，提示"文件已在磁盘上被修改"，让用户选择"覆盖"或"重新载入"。 |

Agent 写入、外部编辑器和云端拉取都按外部修改处理。素材被重命名或移动不影响编辑，被删除时保留编辑内容并提示另存。

## 与其他功能的关系

- **文件引用：** 保存后由现有的引用提取更新关系图。编辑器里引用目标不存在时显示红色标记，与预览一致。
- **查找：** 现有的预览查找继续可用。
- **画板：** 画板里的 Markdown 卡片仍是只读摘录，双击打开的编辑视图可以修改。
- **聊天里的预览：** 聊天和画板卡片继续使用现有只读渲染，编辑器不替换它们。

## 验证

- 打开一个文件、不输入任何内容后切走，磁盘文件的字节和修改时间不变。
- 编辑一段后，其余文本逐字节不变，包括 `*` 与 `-` 列表符号、表格对齐空格和末尾空行。
- 含 BOM 或 `\r\n` 的文件保存后风格不变。
- 编辑过程中外部修改同一个文件：无未保存内容时自动载入新内容，有未保存内容时保存提示冲突，选"覆盖"后磁盘为编辑器内容，选"重新载入"后丢弃编辑内容。
- 输入中文拼音和日文输入法时，组合输入过程中不触发保存，也不丢字。
- 编辑 `[[产品/说明]]` 的路径后保存，关系图中的边随之变化；目标不存在时红色标记和预览一致。
- 超过 2 MiB 的文件只读并提示。
- Windows 与 macOS 上保存、外部修改和换行都能通过同一组测试。

## 暂不做

- 块拖拽、块工具栏、多列和数据库视图。
- 多人协同编辑。
- 评论和修订历史。
- YAML 属性面板，与文件引用第一版的范围保持一致。
- 粘贴图片自动存入素材库，可作为后续独立功能评估。
